# Telegram-бот расписания (ruz.guz.ru)

Бот показывает расписание пар для группы **Б.МН.25.Б3** и раз в
20 минут (настраивается) проверяет сайт `ruz.guz.ru` — если что-то
поменялось (пара сдвинулась, поменялась аудитория/препод, пару
добавили или отменили), бот сам пришлёт сообщение всем, кто подписан.

## ⚠️ Важно прочитать перед деплоем

Сайт ruz.guz.ru — это одностраничное приложение, которое подгружает
расписание через свой собственный JSON-API (адреса вида
`/ruz/api/search`, `/ruz/api/schedule/group/{id}`). Я не могу открыть
такой сайт «как браузер» и подсмотреть реальные адреса и формат
ответа, поэтому в `ruz_client.py` зашита **самая распространённая**
схема такого API (она используется на многих похожих вузовских
сайтах). Она может отличаться от настоящей на 100% совпадать не
обязана.

**Поэтому первый шаг — не деплой, а проверка:**

```bash
pip install -r requirements.txt
cp .env.example .env      # 8898821078:AAHZ9E4G6L9DH_zG74KuTYuzeZOmJ2QSYrs
python check_api.py
```

Скрипт скажет:
- ✅ всё нашлось и поля выглядят нормально — можно деплоить;
- ❌ что-то не так — и подскажет, что именно поправить в
  `ruz_client.py`. Там же, в самом верху `check_api.py`, есть
  инструкция «как за 2 минуты в DevTools браузера подсмотреть
  настоящие адреса API», если понадобится подправить вручную.

Это разовая правка на 5–10 минут, дальше бот работает сам.

## Что делает бот

- `/start` — знакомство, подписка на уведомления
- `/today`, `/tomorrow` — расписание на день
- `/week`, `/nextweek` — расписание на неделю
- `/check` — проверить изменения прямо сейчас
- `/subscribe`, `/unsubscribe` — управление уведомлениями
- Каждые `CHECK_INTERVAL_MINUTES` минут бот сам сверяет сайт с
  последним сохранённым снимком расписания и присылает разницу:
  добавленные/убранные/изменённые пары.

## Деплой на Railway (бесплатный хостинг)

1. Зарегистрируйся на [railway.app](https://railway.app) (можно через GitHub).
2. Залей эту папку в свой GitHub-репозиторий (или используй
   Railway CLI / "Deploy from local").
3. В Railway: **New Project → Deploy from GitHub repo** → выбери репозиторий.
4. Railway сам увидит `requirements.txt` и `Procfile` (тип `worker`).
   Убедись, что запускается именно **worker**, не web-сервис — у
   бота нет http-порта, он всё время слушает Telegram (polling).
5. Во вкладке **Variables** добавь переменные окружения из
   `.env.example` (`BOT_TOKEN`, `GROUP_NAME` и т.д.) — сам файл
   `.env` в репозиторий заливать не нужно.
6. Deploy. В логах должно появиться "Бот запущен...".

### Важно про хранение состояния

Бот хранит подписчиков и последний снимок расписания в файле
`state.json` рядом с кодом. На части бесплатных хостингов (в т.ч.
Railway при пересборке) файловая система эфемерна — при передеплое
файл может обнулиться, и бот один раз посчитает всё расписание
"новым" (без рассылки — это учтено в коде: стартовый снимок при
первом запуске сохраняется молча). Подписчиков придётся набрать
заново через `/start`, если это случится. Если хочешь более
надёжное хранение — можно подключить Railway Volume (постоянный
диск) и указать `STATE_FILE=/data/state.json`, тогда файл переживёт
передеплой.

## Деплой на Render

Аналогично: **New → Background Worker**, подключить репозиторий,
Start Command: `python bot.py`, добавить переменные окружения.
Для сохранения `state.json` между деплоями подключи Render Disk.

## Локальный запуск для теста

```bash
pip install -r requirements.txt
cp .env.example .env   # вписать BOT_TOKEN
python check_api.py    # проверить, что API отвечает как ожидается
python bot.py           # запустить бота
```

## Структура проекта

```
bot.py           — команды бота, планировщик проверок
config.py        — настройки (.env)
ruz_client.py     — обращение к API сайта расписания
diff.py           — сравнение старого/нового расписания
formatting.py     — красивый вывод в Telegram
storage.py        — хранение подписчиков и снимка расписания (state.json)
check_api.py       — диагностика перед первым деплоем
```
